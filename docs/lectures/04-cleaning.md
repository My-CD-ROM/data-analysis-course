# Лекція 4. Чищення даних

*Дані, які приходять із реального джерела — форми, датчика, кількох
об'єднаних таблиць — майже завжди мають дефекти: пропущені значення,
задвоєні рядки, числа, прочитані як текст, і значення, які виглядають
неможливими. Чищення — не разова процедура "прибрати сміття", а набір
осмислених рішень: що робити з кожним типом дефекту і чому саме так.*

## Пропуски

Пропущене значення — це `NaN` (для чисел), `None` (для об'єктів) або
`NaT` (для дат). Причин, чому воно з'явилось, багато: поле не
заповнили, датчик не спрацював, рядки з різних джерел об'єднались не
повністю. **Перш ніж щось виправляти, потрібно зрозуміти, скільки
пропусків і де:**

```python
df.isna().sum()          # кількість пропусків у кожному стовпці
df.isna().mean() * 100    # те саме у відсотках від загальної кількості рядків
```

Дві основні стратегії:

- **`dropna()`** — видалити рядки (або стовпці) з пропусками. Має сенс,
  коли пропущених рядків мало (скажімо, менше 5%) і немає підстав
  вважати, що вони пропущені не випадково.
- **`fillna()`** — заповнити пропуск: константою, середнім, медіаною,
  модою (для категоріальних даних) або методом заповнення вперед/назад
  (`ffill`/`bfill`, типово для часових рядів, де сусіднє значення —
  найкраща оцінка).

```python
df["вік"].fillna(df["вік"].median(), inplace=True)     # медіана стійкіша до викидів, ніж середнє
df["категорія"].fillna(df["категорія"].mode()[0], inplace=True)
df["температура"].fillna(method="ffill", inplace=True)  # часовий ряд — попереднє значення
```

**Чому вибір стратегії — не технічна деталь, а рішення про сенс даних.**
Заповнення середнім штучно зменшує розкид даних (усі заповнені значення
однакові — рівно середнє), що згодом спотворює стандартне відхилення,
яке рахуватимете в Лекції 6. Видалення рядків, навпаки, безпечне для
розкиду, але зменшує вибірку і, якщо пропуски не випадкові (наприклад,
респонденти з низьким доходом частіше не вказують дохід), спотворює
результат систематично, а не випадково.

## Дублікати

Повністю однакові рядки найчастіше з'являються при об'єднанні даних із
кількох джерел або повторному імпорті того самого файлу:

```python
df.duplicated().sum()                          # скільки повністю однакових рядків
df.drop_duplicates(inplace=True)               # прибрати їх, залишивши перший

df.duplicated(subset=["email"]).sum()          # дублікат за одним полем, а не за всім рядком
df.drop_duplicates(subset=["email"], keep="last", inplace=True)
```

Параметр `subset` тут принциповий: два рядки можуть бути "дублікатами"
за бізнес-логікою (той самий email), навіть якщо решта полів
відрізняється (оновлена адреса, нове ім'я) — і навпаки, повністю
однакові рядки не завжди помилка (два клієнти справді могли зробити
однакове замовлення того самого дня).

## Типи даних

Дані з CSV чи форми часто мають "правильний" на вигляд, але хибний тип:
число, прочитане як текст через символ валюти чи роздільник тисяч, дата
у вигляді рядка.

```python
df["ціна"] = df["ціна"].str.replace(" ", "").str.replace("грн", "")
df["ціна"] = pd.to_numeric(df["ціна"], errors="coerce")    # некоректні значення -> NaN, а не помилка

df["дата"] = pd.to_datetime(df["дата"], errors="coerce", dayfirst=True)
```

**Чому `errors="coerce"` — палиця з двома кінцями.** Без нього одне-єдине
некоректне значення в стовпці на 100 000 рядків зупинить обробку
винятком; з ним обробка продовжиться, а зіпсовані значення тихо стануть
`NaN`. Правильна практика — завжди перевіряти `df["ціна"].isna().sum()`
**до і після** такого перетворення: якщо кількість пропусків зросла,
частина даних була втрачена мовчки, і варто зрозуміти чому, а не просто
піти далі.

## Кодування й узгодження категорій

**Кодування тексту.** Український текст, збережений не в UTF-8 (типово
— у застарілому Windows-1251), при неправильному прочитанні
перетворюється на нечитабельний набір символів ("крякозябри"). Якщо
`pd.read_csv("data.csv")` видає такі символи замість кирилиці, потрібно
явно вказати кодування:

```python
df = pd.read_csv("data.csv", encoding="cp1251")   # якщо файл не в UTF-8
```

**Узгодження категорій.** Та сама категорія часто записана по-різному
через регістр, пробіли чи синоніми: `"Київ"`, `"київ "`, `"KYIV"` — для
людини це очевидно одне місто, для `groupby` — три різні групи:

```python
df["місто"] = df["місто"].str.strip().str.lower()
df["місто"] = df["місто"].replace({"kyiv": "київ", "kiev": "київ"})
```

Перевірити, чи лишились неузгоджені варіанти, найпростіше через
`df["місто"].unique()` — переглянути весь список унікальних значень
одним викликом і візуально знайти дублікати змісту.

## Викиди й аномальні значення

Викид — значення, яке сильно відхиляється від решти вибірки. Причина
може бути технічною (помилка вводу — зайвий нуль, збій датчика) або
змістовною (справді рідкісна, але реальна подія) — і це розрізнення
визначає, що з викидом робити.

**Метод міжквартильного розмаху (IQR).** Найпоширеніший формальний
критерій. Якщо відсортувати всі значення стовпця за зростанням,
**квантиль** — це точка, яка ділить ряд у певній пропорції: `Q1` (25-й
процентиль) — нижче нього лежить чверть значень, `Q3` (75-й
процентиль) — нижче нього три чверті. `IQR` — це відстань між ними,
тобто діапазон, де лежить "середина" даних:

```python
df = pd.DataFrame({"зарплата": [28000, 31000, 29500, 33000, 30500, 32000, 250000]})

q1, q3 = df["зарплата"].quantile([0.25, 0.75])    # q1 = 30000, q3 = 32500
iqr = q3 - q1                                      # 2500
lower, upper = q1 - 1.5 * iqr, q3 + 1.5 * iqr      # [26250, 36250]

outliers = df[(df["зарплата"] < lower) | (df["зарплата"] > upper)]
print(outliers)
#    зарплата
# 6    250000   <- єдине значення поза межами [26250, 36250]
```

**Метод z-оцінки.** Альтернатива, зручна коли розподіл ближче до
нормального: показує, на скільки стандартних відхилень значення
відхиляється від середнього, `z = (x - mean) / std`. Традиційний поріг
— `|z| > 2` або `|z| > 3`, залежно від того, наскільки строго шукати
викиди:

```python
df = pd.DataFrame({"бали": [72, 75, 70, 74, 73, 71, 40]})

mean, std = df["бали"].mean(), df["бали"].std()
df["z"] = (df["бали"] - mean) / std

print(df[df["z"].abs() > 2])
#    бали         z
# 6    40 -2.246182
```

Варто зауважити: для прикладу із зарплатою z-оцінка викиду 250000 дає
лише `z ≈ 2.27` — за строгим порогом `|z| > 3` вона взагалі не
позначила б цей викид, бо сам викид спотворює середнє й `std`, за
якими рахується z-оцінка. Тут `IQR` надійніший, бо рахується через
квантилі, менш чутливі до одного екстремального значення — ще один
доказ, що формальний критерій це підказка, а не автоматичне правило.

**Чому "видалити викид" — не завжди правильна відповідь.** Формальний
критерій (IQR чи z-оцінка) лише **позначає підозрілі значення** —
рішення, що з ними робити, приймає людина, яка розуміє контекст даних.
Зарплата в 100 разів вища за медіану може бути помилкою вводу коми, а
може бути зарплатою власника компанії в наборі даних співробітників —
у другому випадку видалення спотворить аналіз більше, ніж сам викид.

## Типові помилки

**Заповнення пропусків середнім без перевірки розподілу.** Для
розподілу з викидами медіана — набагато стійкіший вибір; середнє в
такому разі саме й "тягнеться" до викидів.

**`drop_duplicates()` без явного `subset`.** Видаляє тільки рядки,
однакові повністю — рядки-дублікати за бізнес-змістом (той самий клієнт
з незначною відмінністю в одному полі) залишаються непоміченими.

**Не перевірити `dtype` і кількість `NaN` після `pd.to_numeric` чи
`pd.read_csv`.** `errors="coerce"` мовчки перетворює зіпсовані значення
на `NaN` — без порівняння "до/після" втрата даних лишається непоміченою.

**Автоматичне видалення всіх викидів за формулою.** IQR та z-оцінка —
підказки для подальшого дослідження, а не автоматичне правило видалення;
рідкісне, але реальне значення — це не помилка, яку потрібно виправити.

## Підсумок

- Пропуски виявляють через `isna()` і вирішують або видаленням
  (`dropna`), або заповненням (`fillna`) — вибір впливає на подальшу
  статистику, а не лише "заповнює дірку".
- Дублікати шукають через `duplicated()`/`drop_duplicates()`, і параметр
  `subset` визначає, що саме вважається дублікатом.
- Типи даних приводять через `astype`/`pd.to_numeric`/`pd.to_datetime`
  з `errors="coerce"`, обов'язково перевіряючи кількість `NaN` до і
  після.
- Кодування тексту (UTF-8 проти cp1251) і узгодження категорій
  (`str.strip()`, `str.lower()`, `replace()`) прибирають технічно різні,
  але змістовно однакові значення.
- Викиди виявляють формально (IQR, z-оцінка), але рішення, що з ними
  робити — видалити, дослідити чи залишити — завжди залежить від
  контексту даних.
